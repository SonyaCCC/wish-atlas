# 祈愿手账 · Wish Atlas

原神本地抽卡统计工具。提供独立 Windows x64 桌面分享版，以及 Node.js 22+ 的源码运行方式。中文界面，数据保存在本机。

**[下载 Windows 桌面版](https://github.com/SonyaCCC/wish-atlas/releases/latest)** · [更新记录](RELEASE_NOTES.md) · [使用说明](给朋友的使用说明.md)

下载 Release 中的 `WishAtlas-版本-windows-x64.zip`，不要下载自动生成的 Source code。公开发布包没有任何玩家的 UID、抽卡档案、授权链接或缓存。首次使用请同步或导入自己的记录。

## 祈愿灵感

新功能统一放在「祈愿灵感」，不挤占原有总览。顶部切换三个栏目：

- **趣味报告**：连续 10 / 30 / 100 抽多金窗口、最难忘完整 UP 周期、五星常客榜、年度名场面。走势、日历和下一金假设放在可展开区域，称号附明确条件。
- **时光档案**：角色 / 武器每次获得的时间线、五星时间长卷。只统计抽卡获取次数，不假定实际命座或精炼。
- **分享工坊**：祈愿名片、单角色 / 武器纪念卡、长卷、双账号对比卡，三种主题；可填昵称、签名，隐藏 UID，保存 PNG 或全部分页 ZIP。生成图片完全在本机，不上传记录。

支持全部历史、今年、本月、自定义日期与卡池筛选。统计按账号服务器时间。窗口不跨卡池、已标记断档或简化补录；平均花费不强算被日期筛选截断的首个区间。年度名场面基于收录记录，没有全服排名或幸运时辰预测。

集录祈愿支持手动结果显示与独立不歪率统计；不会用角色池规则自动判断集录结果，也不跨期推算定轨或目标花费。

桌面版：完整解压分享包，双击“祈愿手账.exe”，无需 Node.js 或外部浏览器。1.3.1 起记录固定保存在 `%APPDATA%/WishAtlas/data/`，与 EXE 版本目录分开；具体操作见“给朋友的使用说明.md”。

## 启动

Windows 双击 **启动祈愿手账.cmd**。自动启动本地服务并打开浏览器；也可运行 `node server.mjs`，访问 http://127.0.0.1:3210 。仅监听本机，不开放局域网。

当前电脑可直接使用已有的 Node 运行时。在另一台电脑使用需要安装 Node.js 22 或更新版本。退出网页不会停止后台服务；可在任务管理器停止对应 `node server.mjs` 进程。

如果需要重新启动后台服务，双击 **重启祈愿手账.cmd**。同步期间会拒绝重启，避免中断正在获取的记录。日常使用请从 Windows 资源管理器双击启动文件，不要在限制网络或文件读取权限的环境中启动后台服务；无需管理员权限。

## 同步故障提示

默认使用增量同步：按官方返回的 UID、卡池检查记录，连续 20 条抽卡 ID、时间、物品、星级等一致时，停止该卡池向前翻页。窗口可以跨页；角色双池共享匹配窗口。只合并新增记录，保留原有手动标记，没有新增时不改写档案。新账号、本地不足 20 条或未匹配成功时，会读取官方可查询的全部历史。

若要补查旧记录或断档，在「导入与备份 → 同步方式」选择「完整同步」。增量同步只确认衔接处，不能证明更早的本地历史没有缺口。文件导入仍完整校验并按 ID 去重，避免漏掉文件中的更早记录。切换同步方式会重新读取，不复用另一模式的中断进度。

- “联网权限被运行环境拒绝”或“没有权限读取原神日志”：重新从资源管理器启动或重启本工具。旧版本可能将这些错误统一显示成“拉取失败”或“没有找到历史链接”。
- “历史链接已过期”：在游戏里重新打开祈愿历史，重新获取链接。
- DNS、超时、证书、HTTP 和官方接口错误码分别显示具体原因；这些失败不会改动已保存的记录。
- 临时网络错误会逐步延长等待后重试。若最终仍失败，已读取进度暂存在后台内存中；保持后台运行，使用同一历史链接再次同步即可接着读取。重启后台或换授权链接会重新开始，未完成的数据不写入正式档案。

## 使用

1. 在「导入与备份」选择 UIGF JSON，自动识别 UID 并合并去重；支持 UIGF 2.x / 3.x / 4.x 的原神记录。
2. 或先在 PC 游戏内打开祈愿历史并翻页，点击「自动读取本机记录并同步」。若游戏缓存位置或格式变化导致未找到，粘贴带 authkey 的官方祈愿历史链接即可。无需账号密码，不执行远程 PowerShell 脚本。
3. 更早的数据在「手动补录」中添加。先创建实际 UID 的账号，可选择逐抽补录或五星区间补录。
4. 「历史衔接设置」填写历史起点已垫抽数、大小保底状态。只有确认连续时才勾选补录与明细衔接；有缺口时在断档后的第一条记录上标记断档。
5. 「抽卡记录」可搜索、按卡池/星级筛选、标记五星结果和武器定轨、删除手动补录。
6. 经常导出完整备份，复制到其他位置。完整备份包含补录和手动标记；UIGF 导出仅包含原始真实逐抽记录。

## 数据与统计口径

- API 分页拉取 301 / 302 / 200 / 500 / 100；301 接口包含角色活动双池，计算时 301 / 400 合并。
- UID 隔离、原始抽卡 ID 字符串去重，避免长整数精度丢失。导入先完整校验，再一次性合并保存；分页失败不覆盖已有记录。
- 内置 Paimon.moe 卡池日历，按账号服务器时间判断 UP。更新日历：`node scripts/update-banners.mjs`。脚本只解析字面量数据，不执行下载的 JS。
- 卡池日历只覆盖能完整解析中文五星名称的期数；缺失日期、未知物品或不适用卡池不强行判定。手动标记优先。
- 小保底不歪率 = 小保底不歪 /（小保底不歪 + 歪）。大保底、未知样本排除。无法从官方日志识别捕获明光；自行确认后标记，计入最终不歪。
- 五星平均花费 = 已知完整五星区间平均抽数 × 160。UP 平均花费 = 完整 UP 周期平均抽数 × 160（包含中间歪的抽数）。未完成的尾部垫抽不计入平均数。
- 折合原石不是充值金额，免费祈愿也按 160 折算；新手池折扣不另算。角色和武器花费分别在对应卡池查看。
- 武器“不歪”指当期任意 UP，与是否抽中定轨目标分开。命定值不从缺失信息中推算；上一金 UP 但未确认命中定轨时，下一金保底状态保留未知，避免把定轨保底误当小保底胜利。集录池也不套用角色池规则。
- 首金历史不完整时用 ≥ 显示，排除该区间的平均数。已知垫抽可在设置中恢复；起始垫抽不增加已收录总抽数。
- 简化补录区间只允许早于该池全部逐抽记录；不能夹在真实明细中重复记账。它记录一次五星及其抽数，不伪造中间明细。所有抽数归在出金月份，不用于明细五星率。
- 其他指标：各卡池总抽数、折合原石、五星/四星数量、当前垫抽、大小保底状态、最早/最晚出金、中位数、出金分布、月度抽数、小保底连胜、定轨命中率、待确认记录数。

## 保存与备份

桌面版的 `%APPDATA%/WishAtlas/data/records.json` 保存所有账号，源码版仍使用项目 `data/records.json`。实际路径会显示在「导入与备份」。每次写入前备份旧文件，对应 `backups/` 保留最近 30 份。关闭浏览器不影响数据。完整备份导入是合并式恢复，已存在记录的标记与设置保留，不覆盖用户后来修改；要精确恢复某一快照，请先停止服务，另行保留当前数据文件，再将快照复制为 `records.json`。

authkey 仅在一次同步期间保留在内存中，不保存、不记日志。网页接口采用每次启动生成的 token 和来源检查；历史链接仅发送到固定官方 API 域名，不接受任意服务器代理。

## 验证

运行 `node --test tests/*.test.mjs`。覆盖大小保底边界、断档、简化补录、UP 花费、UIGF 去重、多账号、API 分页/失败、服务落盘等。

没有实际游戏历史链接时，API 的端到端真实账号同步无法验证；自动缓存提取还依赖当前游戏的日志与缓存布局。

## 桌面版打包

`node scripts/update-items.mjs` 更新物品星级资料；`node scripts/download-electron.mjs` 下载固定版本的 Electron 官方 Windows x64 运行时并校验 SHA-256。运行 `powershell -File scripts/package-desktop.ps1 -IncludeData` 生成附带项目 data/records.json 快照的应用目录；不带 `-IncludeData` 则生成空档案版。打包只复制应用、许可与正式 records.json，不复制授权链接、自动备份、日志或测试数据。官方运行时许可证保留在发布目录。

公开发布使用 `pwsh -File scripts/package-desktop.ps1` 和 `pwsh -File scripts/archive-desktop.ps1`，生成空档案 ZIP 和 SHA-256 文件；含档案包仅供自己私下分享，不上传公开仓库。

## 通过 GitHub 发布更新

`main` 的提交与 Pull Request 自动运行测试；推送 `v版本号` 标签会测试、下载并校验 Electron、打包空档案 Windows 版、自检启动，再创建 GitHub Release 并上传 ZIP 与校验文件。流程见 [.github/workflows/release.yml](.github/workflows/release.yml)。

1. 修改功能、测试，更新 `package.json`、`public/core.mjs` 的 UIGF 导出版本、界面版本说明和 `RELEASE_NOTES.md`。
2. 执行 `node --test tests/*.test.mjs` 与 `node scripts/check-release.mjs`，确认通过后提交并推送 `main`。
3. 创建匹配的标签，例如 `git tag v1.3.1`，再运行 `git push origin v1.3.1`。
4. 在 Actions 检查发布完成。朋友始终访问上方固定的最新版下载链接。

1.3.1 及以后，桌面版更新直接沿用固定数据目录；无需每次重新导入。记录始终在本机，GitHub 不托管或同步玩家数据。软件内「统计说明 → 版本与更新」可打开最新 Release；当前采用手动下载更新，不会静默安装。

## 升级时的数据保护

- 桌面版所有新版本使用同一 Windows 用户下的 `%APPDATA%/WishAtlas/data`。解压、替换 EXE 或删除旧程序目录不会触及此数据目录；跨 Windows 用户或电脑仍需导出 / 导入完整备份。
- 首次迁移会查找当前程序旁的旧 data 和同目录内可识别的旧版 WishAtlas 文件夹。只有一份可用旧档案时自动复制；有多份或找不到时，提示选择旧版 records.json / 完整备份，或明确选择首次使用空档案。
- 迁移逐字节复制、检查全部账号与记录格式，校验 SHA-256 相同；手动补录、标记、备注和设置一起保留。原文件不删除，另存 migration-* 备份，不受最近 30 份快照的轮换影响。
- 固定目录一旦已有 records.json（即使为空），之后的更新包或旧快照都不能覆盖它。格式损坏、写入或校验失败会停止启动，不会静默创建空档案。
- 新版之间使用同一桌面配置目录和单实例锁，避免同时写入。迁移后请使用新版；1.3.0 及更早版本仍读旧目录，不会与新版双向同步。源码浏览器版也保留独立的项目数据目录。
- 普通“导入完整备份”是合并：新增记录会补入，已存在记录的当前标记和设置优先。首次迁移则原样复制，二者用途不同。
- 每次公开发布都执行桌面迁移自检，验证首次迁移以及再次启动不会丢失账号、补录、备注和设置。
